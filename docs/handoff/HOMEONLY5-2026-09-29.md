# HOMEONLY5 — USER11 stack trace after corrected HOMEONLY4 interpretation

Date: 2026-09-29

## Corrected HOMEONLY4 device result

The HOMEONLY4 screenshots/video initially looked like touch had begun working in Home.
The device log proves a different sequence:

1. Real Home UID 0x102750F0 launches and renders.
2. At 16:48:51.938 the real Home thread panics:
   - category USER
   - reason 11
3. HOMEONLY3 containment prevents the host emulator from rebooting and leaves the most recent Home framebuffer visible.
4. About 5 ms later WindowServer focus is group 2, belonging to Menu3.
5. At 16:49:11 the user taps the visually stale Home softkey "Telephone".
6. That pointer event is actually delivered to:
   - client_thread 176
   - window group 2
   - Menu3 UID 0x101F4CD2
7. Menu3 consumes GetEvent and opens its Options menu over the stale Home framebuffer.

Therefore:
- real Home touch is NOT yet working;
- the visible Home image after 16:48:51.938 is stale;
- the Options popup shown in the screenshots belongs to Menu3;
- HOMEONLY4 EventReady probing is not the next bottleneck because the tested touch happened after Home was already dead.

## USER 11 boundary

The final Home Central Repository operation immediately before panic is:

- repository 0x10275104
- key 0xA0001000
- entry_len = 52
- destination max = 2048
- write_len = 52
- status = 0

So the observed CenRep write itself does not exceed its destination descriptor.

The Symbian USER/11 panic class is associated with 16-bit descriptor overflow / assignment of data longer than a target descriptor.

Current working hypothesis:
Home receives the CenRep string successfully, then a later guest-side descriptor operation copies/assigns data into a smaller descriptor and triggers USER/11.

Do NOT change CenRep string lengths/content until the guest callsite is identified.

## Next decision

Use USER11_FRAME module + offset to decide the actual semantic fix.

- If the first caller outside euser.dll is Home/a Home plugin:
  identify the descriptor operation and the expected input maximum.
- If it points into Central Repository client glue:
  compare EKA2L1 GetString ABI/length semantics to Symbian.
- If it points to a different framework DLL:
  inspect that subsystem instead.

Do not patch the symptom by suppressing USER/11.
