# HOMEONLY6 — Generic quoted CenRep tokenizer backport

Date: 2026-09-29

## Scope

Hướng 1 only: MENUUI36 NOJAVA -> Menu3 -> real Home UID 0x102750F0.

Do not use NativeBoot, CompatBoot or DirectHome.
Do not alter CenRep 52-byte -> 26-character semantics.
Do not suppress USER/11.

## HOMEONLY5 root-cause evidence

Exact RM-356 firmware binaries were reconstructed and hash-verified against the HOMEONLY5 handoff.

The first non-euser return frame at aiscutplugin.dll +0x475A is immediately after a Thumb BLX at +0x4756 to the import veneer at +0x595C. The veneer belongs to euser.dll (ordinal 953).

aiscutplugin.dll +0x6F60/+0x6F64 is data, not executable code:
- +0x6F60 stores the length-prefixed literal region
- +0x6F64 begins UTF-16 "iconid"

The exact RM-356 file Z:\\private\\10202BE9\\10275102.txt contains:

    localapp:0x101F4CD2?iconid=270501603;7110&toolbar=1

That value is 51 UTF-16 code units / 102 bytes. Its first '=' is at index 26.

HOMEONLY5 immediately before USER/11 observed:
- repo 0x10275104
- key 0xA0001000
- entry_len 52 bytes
- successful GetString

52 bytes = 26 UTF-16 code units, exactly the prefix before the first '=':

    localapp:0x101F4CD2?iconid

## Baseline parser defect

HOMEONLY2..5 ultimately use EKA2L1 upstream Git HEAD:

    661031f9d8ccd37612797e32a52b2d4c6aadfcdc

In src/emu/common/src/ini.cpp at that baseline, ini_linestream:
1. enters quoted-token mode by stopping at the next double quote;
2. still executes trim1.find('=');
3. therefore splits '=' inside quoted values as key/value syntax;
4. does not consume the closing quote before reading the next token.

This is a generic INI/CenRep tokenizer defect. Current upstream EKA2L1 uses quote-aware tokenization semantics.

## HOMEONLY6 delta

apply_homeonly6_cenrepquoted1.py backports only the generic behavior required by the old baseline:
- track whether the current token is quoted;
- comma/tab remain literal while quoted;
- consume the closing quote;
- return quoted content before applying key=value splitting.

No target-specific values are embedded in src/emu/common/src/ini.cpp.

Preserved unchanged:
- HOMEONLY5 USER11 diagnostics
- HOMEONLY4 event diagnostics
- HOMEONLY3 containment
- MENUUI36/MENUUI35/MENUUI33/MENUUI31/MENUUI30 baseline behavior
- CenRep server byte-length ABI
- NativeBoot absent
- CompatBoot absent
- J2ME absent

## Expected device signal

On HOMEONLY6, the CenRep GetString for the same shortcut should no longer be the 52-byte prefix caused by quote splitting. The full source value is 102 bytes.

The primary pass/fail signal is:
1. Home no longer panics USER/11 on this path.
2. Existing HOMEONLY1 CEN_GET_STRING diagnostics show the corrected value length/content flow.
3. Home remains the real UID 0x102750F0 route launched from Menu3.

Do not introduce a 52->26 length conversion. Symbian TDes16 client semantics already account for UTF-16 units.
