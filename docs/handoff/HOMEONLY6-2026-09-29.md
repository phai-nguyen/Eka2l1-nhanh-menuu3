The apparent +0x6F60/+0x6F64 values are static UTF-16 data/literals, not reliable call frames.

## Central Repository length hypothesis rejected

Do NOT change CenRep's server-side returned length from 52 to 26.

Authoritative Symbian Central Repository source
`persistentstorage/centralrepository/pccenrep/src/pccenrep.cpp`
implements the 16-bit overload by wrapping the 16-bit target as TPtr8, calling
the byte-oriented Get(), then dividing by two in the client wrapper:

```cpp
EXPORT_C TInt CRepository::Get(TUint32 aKey, TDes16& aValue, TInt& aActualLength)
{
    TInt actualLength8;
    TPtr8 ptr8((TUint8*)aValue.Ptr(), 0, aValue.MaxSize());
    TInt ret=Get(aKey,ptr8,actualLength8);
    aValue.SetLength(ptr8.Length()/2);
    aActualLength=actualLength8/2;
    return ret;
}
```

Therefore a 52-byte UTF-16 payload and byte-length 52 from the server are
consistent with the original ABI.

## Binary reverse engineering of aiscutplugin.dll

RM-356 firmware binary:
`Z:\sys\bin\aiscutplugin.dll`

SHA-256:
`82bc75a917de8fda87a41fc49894c1928a075af99a6a89f1fa7ec61352be0221`

The function around +0x46EC parses a descriptor/string and includes this path:

- TDesC16::Alloc()
- HBufC16::Des()
- TDesC16::FindC()
- TDes16::Delete()
- TDesC16::Locate('&')
- TDesC16::Mid(...)
- TDes16::Copy(...)

The HOMEONLY5 stack value:
`0x7280475B`
is the return address immediately after the TDes16::Copy import call at
aiscutplugin +0x4756.

The imported euser ordinal for that call is:
- ordinal 953
- `TDes16::Copy(const TDesC16&)`

Thus the USER/11 boundary is directly associated with a 16-bit descriptor copy
inside the Active Idle shortcut plugin.

The same binary contains UTF-16 shortcut metadata field names around +0x6F60:
- iconid
- iconmifpath
- iconpath
- customtitle

This strongly indicates the failing function is parsing/copying structured
shortcut metadata, but HOMEONLY5 alone does not reveal the exact source/target
descriptor Length/MaxLength pair.

## HOMEONLY6 probes

### 1. SHORTCUTVALUEPROBE1

Patch:
`apply_homeonly6_shortcutvalueprobe1.py`

Marker:
`[HOMEONLY6][CEN_SHORTCUT_VALUE]`

For small GetString values from repository 0x10275104, log:
- key
- byte length
- UTF-16 unit count
- complete payload as hex
- readable low-byte text rendering

Semantics unchanged:
- repository data unchanged
- returned bytes unchanged
- actual length unchanged
- completion status unchanged

### 2. DESCSCAN1

Patch:
`apply_homeonly6_descscan1.py`

Marker:
`[HOMEONLY6][DESC_SCAN]`

Only at the already-filtered Home USER/11 panic, scan the same 64-word stack
window captured by HOMEONLY5.

For plausible Symbian 16-bit descriptors found:
- directly inline at stack slots
- through raw guest pointers stored on the stack

log:
- descriptor type
- Length
- MaxLength
- raw descriptor words
- up to 32 UTF-16 units of preview
- UTF-16 hex preview

No guest memory is written.

## Next decision

If DESC_SCAN captures a source descriptor with Length > destination MaxLength,
identify the metadata field/value and fix the upstream generic ABI/data source
that produced it.

Do not:
- suppress USER/11;
- truncate the shortcut value arbitrarily;
- hardcode repository key 0xA0001000 as a semantic fix;
- change CenRep 16-bit actual length from bytes to UTF-16 units at the server.
