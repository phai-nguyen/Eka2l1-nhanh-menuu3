## HOMEONLY3 device result

User reports:
- real Home Screen now remains stable and no longer disappears/crashes;
- Home UI remains rendered for an extended period;
- touch still produces no visible Home response.

Video and log establish:
- Home UID3 = 0x102750F0 launches successfully.
- WindowServer Home client thread = 611.
- Home window group = 30.
- full-screen Home target window = win_id 52, handle 9293680, 360x640.
- Home receives focus.

A real iOS touch reaches the entire input path:
iOS EmulatorView
-> bridge
-> driver
-> WindowServer
-> guest coordinates
-> Home window hit-test
-> Home event FIFO.

Example first touch:
- target handle 9293680
- client_thread 611
- group_id 30
- listener_pending=1
- qsize becomes 1.

Subsequent touches:
- qsize continues increasing
- listener_pending=0
- Home does not issue touch GetEvent.

Home EventReady history before touch:
- EventReady arm at 16:18:55.442
- EventReady arm at 16:18:55.451
- EventReady arm at 16:18:56.012

Home GetEvent before touch only dequeues non-touch events.
After the first touch there is no touch GetEvent and no new EventReady arm.

Therefore the current bottleneck is NOT:
- iOS touch capture
- coordinate conversion
- display scaling
- WindowServer focus
- hit-testing
- FIFO enqueue
- advanced-pointer modifier

It is after FIFO enqueue / EventReady completion, before the Home event loop consumes GetEvent.

## Decision table for next fix

A. EVENT_WAKE shows pending->complete, request_count increases, SEMA_WAKE/dewait occurs:
- EventReady kernel wake works.
- Next target: guest ActiveScheduler / ready CActive recognition after wake.

B. EVENT_WAKE status completes but request_count/semaphore wake is wrong:
- Fix request-semaphore notification path generically.

C. EVENT_WAKE shows active=0 for the EventReady RequestStatus:
- Strong candidate: Home's EventReady status is not being marked as active/associated correctly.
- Investigate CActive/request-status activation semantics; do not force it without confirming ABI.

D. No HOMEONLY4 EVENT_WAKE despite MENUUI14 listener_pending=1:
- Re-check listener ownership / requester identity and WindowServer EventReady client association.

No Home-specific key/repository hardcoding is allowed in the final semantic fix unless used only as temporary diagnostics.
